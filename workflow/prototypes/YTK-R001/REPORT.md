## 旧リスク判定ロジックとの差分

### 旧ロジック

利用中カテゴリごとに保持した詳細情報を集計して5軸を判定していた。

- 本人確認の入口:
  端末・基盤アカウント・メール・通信契約の各カテゴリの引継ぎ／復旧設定を集計
- 継続課金:
  各カテゴリの課金回答を集計
- 金融資産:
  各カテゴリの金融資産回答を集計
- 消失すると困るデータ:
  各カテゴリの重要データ回答を集計
- 家族が存在を知らない可能性:
  各カテゴリの家族把握回答を集計

### 新ロジック

初回結果に必要な5軸を、STEP2の5つの全体質問から直接判定する。

- 本人確認の入口
  - だいたい確認済み → 確認できている
  - 未設定あり → 要確認
  - わからない → 少し曖昧
  - 未回答 → 未回答

- 継続課金 / 金融資産 / 消失すると困るデータ
  - あり → 要確認
  - なし → 確認できている
  - わからない → 少し曖昧
  - 未回答 → 未回答

- 家族が存在を知らない可能性
  - だいたい把握 → 確認できている
  - 知らないものあり → 要確認
  - わからない → 少し曖昧
  - 未回答 → 未回答

### 変更理由

旧ロジックはカテゴリ単位の詳細入力を前提としており、初回体験を重くしていた。

YTK-R001の初回目的は詳細台帳の完成ではなく、
「数回のタップで、自分のデジタル情報の状態をざっくり見えるようにすること」
と再整理した。

精密さを少し下げる代わりに、初回離脱を抑え、結果まで到達しやすい構造を優先した。

個別サービス単位の精密な整理は、初回結果後の追加整理機能に分離する候補とする。
