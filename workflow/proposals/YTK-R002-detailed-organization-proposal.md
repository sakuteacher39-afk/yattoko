## 1. このproposalの目的

YTK-R001の初回軽量フローを完了した利用者が、
必要な場合だけ個別サービス単位まで詳しく整理できる
「詳しく整理する」機能の非公開UX仕様案を定義する。

本proposalでは、
実装前に画面構成・入力負荷・条件分岐・本人意向の継承方法・禁止事項を固定候補として整理する。

このproposal自体は実装承認ではない。
人間承認後にのみ、非公開プロトタイプ制作へ進む。

## 2. 固定条件

以下はYTK-R002次工程の固定条件として変更しない。

1. YTK-R001の軽量フローを維持する
2. 詳細整理を巨大フォーム化しない
3. 共通コア最小限 + 条件付き質問を基本とする
4. カテゴリ本人意向を初期値として継承し、サービス単位では必要時のみ上書きする
5. 秘密情報の入力欄は作らない
6. YTK-R002ではサーバー保存・認証を実装しない
7. 「あとで続ける」はUX設計対象とするが、永続的な再開機能は実装しない
8. サービス情報カタログは例示・UI検証範囲に留め、本格構築しない
9. ロードマップ上の役割分離を維持する
   - YTK-R003: 保存データ仕様
   - YTK-R004: 認証設計
   - YTK-R005: サーバー保存プロトタイプ

## 3. YTK-R001との接続位置

接続位置はYTK-R001のSTEP5「整理結果」とする。

STEP5の初回整理完了そのものは変更しない。

結果画面の主役は引き続き、

- 持っているもの
- 曖昧なもの
- 5リスク軸
- 本人の意向
- 次に確認すること

とする。

「詳しく整理する」は初回整理の必須工程にしない。

### 導線候補

STEP5下部に以下の補助導線を置く。

主候補:
**必要なところだけ詳しく整理する**

補足文候補:
「サービスを1件ずつ追加できます。全部やる必要はありません。」

副導線:
**今日はここで終わる**

「詳しく整理しないと未完了」という印象を与えない。

## 4. 詳細整理の全体フロー

### D0: 詳細整理の入口

表示内容:

- 初回整理は完了していることを明示
- 詳細整理は任意であることを明示
- 1件だけでも終了できることを明示
- 秘密情報は入力しないことを短く再表示

主操作:

- カテゴリを選ぶ
- 今日はここで終わる

### D1: カテゴリ選択

YTK-R001 STEP1で以下だったカテゴリだけを優先表示する。

- 使っている
- わからない

「使っていない」は初期表示しない。

ただし、
「ほかのカテゴリを整理する」から12分類すべてを参照できる候補とする。

初期表示順候補:

1. 「使っている」カテゴリ
2. 「わからない」カテゴリ
3. その他

5リスク軸を根拠に「危険順」へ並べない。
警告ランキング化しない。

### D2: サービスを1件選ぶ

選択したカテゴリ内で、
主要サービスを候補ボタンとして例示する。

例:

B 基盤アカウント
- Apple
- Google
- Microsoft
- その他

D SNS・メッセージ
- LINE
- Facebook
- Instagram
- X
- その他

E クラウド・写真・バックアップ
- iCloud
- Google Drive / Google Photos
- OneDrive
- Dropbox
- その他

候補リストはUI検証用の例示に留め、
YTK-R002で完全なサービス情報カタログを構築しない。

「その他」を選んだ場合だけ、
サービス名の短い自由入力を許可する候補とする。

### D3: 共通コア確認

1件追加時の共通コアは最大3項目とする。

1. サービス名
   - 候補から選択した場合は自動
2. カテゴリ
   - D1から自動
3. 利用状態
   - 利用中
   - 休眠・停止中
   - わからない

サービス名・カテゴリを既に確定できる場合、
画面上では確認表示に留め、
実質的な回答は「利用状態」1問だけでもよい。

### D4: 必要なことだけ追加確認

共通コアの後に、
カテゴリに応じた条件付き質問をタップ式で表示する。

1画面で一気に全部見せない。

原則:
- 1〜3問程度ずつ
- すべて「わからない」を選択可能
- 任意項目はスキップ可能
- 文字入力を原則使わない

### D5: 本人意向確認

YTK-R001のカテゴリ本人意向を初期値として表示する。

例:
「SNS・メッセージでは『残したい』を選んでいます」

選択肢:

- カテゴリと同じ
- 残したい
- 削除したい
- 家族に任せる
- 未決定

デフォルト:
**カテゴリと同じ**

利用者が変更しなければ、
サービス単位の上書き値を作らない候補とする。

### D6: 1件整理完了

表示内容:

- 追加したサービス名
- 利用状態
- 回答した条件付き項目
- 本人意向
- 「わからない」や未回答もそのまま表示

完了操作:

- 同じカテゴリでもう1件追加
- 別カテゴリを整理
- 今日はここで終わる

「次へ」だけで進行を強制しない。

## 5. 共通コア仕様

### 必須候補

#### サービス名

原則は候補選択。
自由入力は「その他」の場合のみ。

入力負荷軽減のため、
主要サービス名を毎回キーボード入力させない。

#### カテゴリ

YTK-R001から自動引継ぎ。
利用者に再選択させない。

変更したい場合のみ戻って選び直せる候補。

#### 利用状態

3択:

- 利用中
- 休眠・停止中
- わからない

「休眠」と「停止中」を分離しない。
YTK-R002では状態粒度を増やしすぎない。

## 7. 本人意向の継承仕様

### 基本

YTK-R001のカテゴリ単位意向を初期値として継承する。

カテゴリ意向:

- 残したい
- 削除したい
- 家族に任せる
- 未決定

### サービス単位

初期状態:
**カテゴリと同じ**

利用者がサービス単位で変更した場合だけ上書きする。

例:

カテゴリ:
SNS・メッセージ = 残したい

サービス:
- LINE = カテゴリと同じ
- Facebook = カテゴリと同じ
- X = 削除したい

Xを削除したいと設定しても、
カテゴリ全体の「残したい」は変更しない。

### 表示上の注意

「カテゴリと同じ」を選択肢として明示し、
現在継承している内容を併記する。

例:
「カテゴリの設定: 残したい」

これにより毎回同じ意向を答えさせない。

## 8. 「あとで続ける」の扱い

YTK-R002では永続保存を実装しない。

そのため「あとで続ける」は、
実際にブラウザを閉じて後日再開できる機能として表現しない。

### UI候補

画面内の中断操作:

**いったん詳細整理を終わる**

説明:
「この非公開試作では、ページを閉じると詳細整理の内容は残りません。」

同一セッション中は、
YTK-R001と同様にJavaScriptメモリ内で状態を維持する候補。

### 禁止する表現

- 保存してあとで続ける
- 次回ここから再開
- 自動保存済み

永続保存があるように誤認させない。

YTK-R003以降で保存仕様が確定した場合に再設計する。

## 9. サービス情報カタログのUI検証

YTK-R002では本格カタログを作らない。

UI検証用として、
カテゴリごとに数件だけ主要サービス例を固定データで持つ候補とする。

例:

```js
{
  category: "base",
  examples: [
    { id: "apple", name: "Apple" },
    { id: "google", name: "Google" },
    { id: "microsoft", name: "Microsoft" }
  ]
}
```

このデータには、
公式手続き情報の完全なデータベースを含めない。

必要であれば、
1〜2サービスについてのみ
「公式案内あり」等の表示例を作り、
UIの見え方だけ確認する。

### R002でしないこと

- 全サービス網羅
- 自動更新
- 外部API連携
- 公式情報の定期監視
- 法的手続きの自動判定
- 最新性保証

## 10. 秘密情報の入力禁止仕様

以下は入力欄を作らない。

- パスワード
- PIN / 暗証番号
- 端末パスコード
- OTP / ワンタイムコード
- OTP生成用シード
- 復旧コード
- 秘密鍵
- シードフレーズ
- カード完全番号
- CVV / CVC
- パスキー秘密情報
- APIキー
- アクセストークン
- SSH秘密鍵
- クラウド秘密鍵
- 秘密の質問の回答
- その他、直接ログイン・送金・資産移動・サービス操作に利用できる秘密情報

### 自由入力

YTK-R002では自由メモ欄を作らない。

サービス名の「その他」入力だけを例外候補とする。

この入力欄にも、
「パスワードなどの秘密情報は入力しないでください」
という短い注意を添える。

## 11. R002内の一時データ構造候補

非公開プロトタイプ内のメモリ状態のみを想定する。

```js
{
  categoryId: "social",
  serviceId: "line",
  serviceName: "LINE",
  usageStatus: "using",
  inheritedIntention: "keep",
  intentionOverride: null,
  answers: {
    importantData: "yes",
    handoverStatus: "unknown",
    recurringCharge: "no"
  }
}
```

### 持たないフィールド

- password
- pin
- passcode
- otp
- otpSeed
- recoveryCode
- privateKey
- seedPhrase
- fullCardNumber
- cvv
- passkeySecret
- apiKey
- accessToken
- sshPrivateKey

### 保存について

この構造はYTK-R002の非公開プロトタイプ内で
メモリ上の一時状態として使う候補であり、
サーバー保存仕様ではない。

YTK-R003の保存データ仕様へ流用することを前提にしない。

## 12. 詳細整理一覧画面の候補

サービスを1件以上追加した場合、
現在のセッション内だけで一覧表示できる候補とする。

表示例:

SNS・メッセージ

- LINE
  - 利用中
  - 本人意向: カテゴリと同じ（残したい）
  - 大事なデータ: ある

- X
  - 利用中
  - 本人意向: 削除したい

操作:

- 詳細を見る / 修正
- もう1件追加
- 別カテゴリへ
- いったん詳細整理を終わる

一覧で未回答を赤いエラーにしない。

「未回答」「わからない」を正常状態として表示する。

## 13. 入力負荷を抑える具体ルール

### 1画面あたり

目安:
- 主質問 1〜3個
- 主ボタン 1つ
- 補助操作 1〜2個

### 文字入力

原則なし。

許可候補:
- 「その他」のサービス名

### 必須回答

共通コアの利用状態以外は、
原則として未回答でも先へ進める候補。

### 完了定義

以下のどれでも正常終了とする。

- 1サービスだけ整理した
- 1カテゴリだけ整理した
- 複数サービス整理した
- 詳細整理をしなかった

「全12分類100%」を完了条件にしない。

### 進捗表示

パーセント進捗は使わない候補。

代わりに:

- 「1件整理しました」
- 「このカテゴリに2件あります」

など件数ベースの軽い表示を使う。

## 14. エラー・例外UX

### サービス名が決まらない

「わからないサービス」として追加するのではなく、
カテゴリに戻り
「サービス名が思い出せない」を選べる候補とする。

この状態を個別サービスレコードにするかは実装前に再確認する。

### 利用状態がわからない

正常回答として保存候補:
「わからない」

### 条件付き質問を飛ばす

エラーにしない。

### 戻る

同一セッション内では入力状態を維持する。

### 最初からやり直す

YTK-R001全体を消す操作と
R002詳細整理だけをやり直す操作を混同しない。

R002側には
「詳細整理だけリセット」
を置く場合も確認ダイアログ候補とする。

## 15. 非公開プロトタイプで確認したいUX

人間レビュー時に以下を確認する。

### 接続

- YTK-R001 STEP5から自然に入れるか
- 詳細整理が必須に見えないか
- 初回整理完了感を壊していないか

### 負荷

- 最初から巨大フォームに見えないか
- サービス1件追加が短時間で終わるか
- 条件付き質問が多すぎないか
- 文字入力がほぼ不要か
- 1件でやめやすいか

### 意向

- カテゴリ本人意向の継承が理解できるか
- サービス単位上書きが必要な時だけ使えるか
- 上書きがカテゴリ全体を変更しないと理解できるか

### 安全

- 秘密情報を入力したくなるUIがないか
- 金融カテゴリでも口座番号・暗証番号等を要求していないか
- 「詳しく整理する」が「ログイン情報を登録する」に見えないか

### 中断

- 「いったん詳細整理を終わる」が自然か
- 永続保存があると誤認しないか

### スマホ

- iPhone Safariで1画面の情報量が重すぎないか
- タップ領域が十分か
- 長いカテゴリ名・サービス名が崩れないか
- 画面下部まで操作しやすいか

## 16. 非公開プロトタイプ制作時の範囲候補

人間承認後に制作部へ渡す場合、
実装範囲候補は以下に限定する。

1. YTK-R001 STEP5からの任意導線
2. D0 詳細整理入口
3. D1 カテゴリ選択
4. D2 サービス候補選択
5. D3 共通コア
6. D4 条件付き質問
7. D5 本人意向継承・上書き
8. D6 1件整理完了
9. セッション内一覧表示
10. セッション内のみの状態保持
11. 「いったん詳細整理を終わる」
12. 秘密情報非入力の注意表示
13. UI検証用の限定サービス候補データ

## 17. YTK-R002では実装しないもの

- サーバー保存
- 認証
