## 1. 制作判断

YTK-R001の12分類を、そのまま12個の長い入力フォームにしない。

ヤットコの初期体験は、
1. 「何を持っているか」を思い出す
2. 「何が曖昧か」を見つける
3. 「どこにリスクがあるか」を把握する
4. 「自分はどうしたいか」を残す

という4段階を中心にする。

ToDo一覧は最終結果の補助表示に留める。

## 3. 初回画面構成案

### 画面0: 安全方針

最初に明示する。

> ヤットコは、パスワードや暗証番号を預かる場所ではありません。
> 「何を使っているか」「どんな状態か」「どうしてほしいか」を整理します。

入力禁止例を短く表示する。

- パスワード
- 端末パスコード
- 暗証番号
- クレジットカード完全番号
- ワンタイムコード
- 復旧コード
- 秘密鍵

### 画面1: 「持っているもの」をざっくり確認

12分類をカードで表示する。

各カードの回答は3択を基本とする。

- 使っている
- 使っていない
- わからない

「わからない」を正常な回答として扱う。
未回答や曖昧さを失敗扱いしない。

### 画面2: 選択カテゴリの詳細確認

カテゴリごとに必要最小限の共通項目を表示する。

共通項目候補:

- サービス名
- 登録識別子
  - メールアドレス
  - 電話番号
  - ユーザー名等
- 課金
  - あり
  - なし
  - 不明
- 金融資産
  - あり
  - なし
  - 不明
- 重要データ
  - あり
  - なし
  - 不明
- 公式の引継ぎ・死後管理・復旧設定
  - 設定済み
  - 未設定
  - 不明
  - 対象外 / わからない
- 本人の希望
  - 残したい
  - 削除したい
  - 家族に判断を任せる
  - 未決定
- 家族へ伝えたい補足

### 画面3: 「気になるところ」可視化

YTK-R001の5リスク軸を、単なる警告一覧ではなくカード／メーターとして表示する。

1. 本人確認の入口
2. 継続課金
3. 金融資産
4. 消失すると困るデータ
5. 家族が存在を知らない可能性

判定表示の例:

- 確認できている
- 少し曖昧
- 要確認
- 未回答

「危険」「安全」と断定しない。
法的・契約上の状態まで自動判定しない。

### 画面4: 「自分はどうしたいか」

サービス単位・カテゴリ単位で本人の意向を確認する。

主な選択肢:

- 残したい
- 消してほしい
- 家族に判断を任せたい
- まだ決めていない

写真・SNS・メッセージ等については必要に応じて:

- 家族に見せたい
- 家族には見せたくない
- 保存してほしい
- 追悼機能等があれば利用したい
- 未決定

### 画面5: 整理結果

単なる「未完了ToDo」ではなく、以下を優先表示する。

#### 持っているもの
12分類のうち利用中・不明のカテゴリを俯瞰表示。

#### 曖昧なもの
「わからない」「未決定」が残っている箇所を表示。

#### 気になるポイント
5リスク軸ごとの状態を表示。

#### 本人の意向
残す / 消す / 家族判断 / 未決定の分布を表示。

#### 次に確認すること
最後に補助的なToDoを最大3〜5件だけ提示する。

## 4. 優先確認グループ

- スマートフォン / 電話番号

「他のサービス確認に影響しやすい項目」と説明する。

## 5. 秘密情報を保存しない仕様

### 入力禁止

以下はフォーム項目自体を用意しない。

- パスワード
- PIN / 暗証番号
- 端末パスコード
- クレジットカード完全番号
- CVV
- ワンタイムパスワード
- MFA復旧コード
- パスキー秘密情報
- 暗号資産秘密鍵 / シードフレーズ

### 自由記述対策

自由記述欄の近くに警告を表示する。

> パスワード、暗証番号、カード番号、復旧コード、秘密鍵などは入力しないでください。

将来サーバー保存を導入する場合は、自由記述への秘密情報混入対策を別途設計する。
現段階では保存方式そのものを本成果物だけで確定しない。
